# Go2W 导航系统启动手册

> 更新日期：2026-10-22
> 适用于新系统：Orin 上的 Humble 容器 `go2w_humble`（ROS_DOMAIN_ID=43）
> 取代旧的《Go2W 三机导航系统完整启动与恢复手册》（Foxy 容器 + Ubuntu 上跑 AMCL 那一套）。旧系统仍保留在容器 `go2w_foxy` 里作为回退，两套不要同时使用雷达。
>
> ⚠️ S7（Nav2 自主导航）还在测试阶段：前几次导航务必低速、手持遥控器随时接管。

## 0. 命令速查（从开机到能动）

所有导航操作都通过 `~/go2w/scripts/nav.sh` 完成：不用进容器、不用 tmux、不用按组合键。导航在后台运行，SSH 断开也不影响。

**第 0 步 · 开机（操作）**
先开 Go2W，让它站好、停在平地上不要动；确认 Orin 的网线插好；再开 Orin，等 1–2 分钟。

**第 1 步 · 登录 Orin（Mac 本地终端）**
```bash
ssh w@192.168.1.111
```

**第 2 步 · 启动导航（Orin 终端）**
```bash
~/go2w/scripts/nav.sh start
```
看到"✅ 导航已启动，里程计正常"再往下走。

**第 3 步 · 打开 RViz（Ubuntu 终端）**
```bash
bash ~/go2w_viz/go2w_rviz.sh
```

**第 4 步 · 设置初始位姿（RViz 操作）**
点 **2D Pose Estimate** → 在机器人的实际位置按下鼠标 → 朝车头方向拖动 → 松开。确认红色的 scan 和墙对得上。

**第 5 步 · 解锁（Orin 终端）**
```bash
~/go2w/scripts/nav.sh arm 
```

**第 6 步 · 发目标（RViz 操作）**
点 **2D Goal Pose** → 在目标位置按下鼠标 → 朝期望的朝向拖动 → 松开。手里拿着遥控器。

**休息 · 上锁（Orin 终端）**
```bash
~/go2w/scripts/nav.sh disarm
```
回来后执行 `~/go2w/scripts/nav.sh arm` 就能继续，不用重新设位姿。

**结束 · 停止（Orin 终端）**
```bash
~/go2w/scripts/nav.sh stop
```

**随时查看状态 / 日志（Orin 终端）**
```bash
~/go2w/scripts/nav.sh status
~/go2w/scripts/nav.sh log
```

**提示**
- 执行 `start` 时提示"导航已经在运行了"：先执行 `~/go2w/scripts/nav.sh stop`，再执行 `start`。
- `status` 显示"里程计不健康"：先 `stop`，确认网线插好、机器人静止，再 `start`。
- 换一张地图：`~/go2w/scripts/nav.sh start /go2w/data/maps/地图名.yaml`
- Mac 键盘上的 Ctrl 就是左下角的 **control（⌃）** 键，不是 ⌘ command。

## 1. 系统组成

| 设备 | 地址 | 作用 |
|---|---|---|
| Go2W 运动主控 | `192.168.123.161` | 接收速度桥发来的运动指令 |
| Go2W PC2 | Wi-Fi `192.168.1.142`，内网 `192.168.123.18`，用户 `unitree` | 新系统中**不参与**；不要在它上面运行雷达驱动 |
| MID360 雷达 | `192.168.1.194`（接在 Go2W 内部交换机上） | 点云和 IMU 直接发给 Orin 的 `192.168.1.51` |
| Orin | Wi-Fi `192.168.1.111`，有线 `192.168.123.222` + `192.168.1.51/32`，用户 `w` | 运行全部导航程序 |
| 外部 Ubuntu | `192.168.1.167`，用户 `dx` | 只用 RViz 看画面、设初始位姿和目标点 |

数据流：

```text
MID360 ──有线──▶ Orin 容器 go2w_humble
                  雷达驱动 → FAST-LIO → 平面里程计 → 2D scan → AMCL（定位）→ Nav2 → 速度桥 ──有线──▶ Go2W 主控
                  │
                  └─ 容器 go2w_viz_bridge（只转发显示用话题）──Wi-Fi──▶ Ubuntu RViz
```

## 2. 重启后哪些自动恢复

| 项目 | 状态 |
|---|---|
| Orin 时间同步（开机后等时间对上再启动容器） | 自动 |
| 容器 `go2w_humble`、`go2w_viz_bridge` | 自动启动 |
| 有线网口 `192.168.123.222` 和雷达用的 `192.168.1.51/32` | 自动 |
| Wi-Fi 省电关闭 | 自动 |
| **导航程序**（雷达驱动、FAST-LIO、定位、Nav2、速度桥） | **手动启动**，见第 3 节第 3 步 |
| **初始位姿、速度桥解锁** | **每次都要手动** |

## 3. 启动步骤

### 第 1 步：开机

1. 先开 Go2W，让它**站起来**，停在**平地上保持静止**。
   FAST-LIO 用开机后最初几秒的数据初始化，这时机器人在动的话，后面的定位会出问题。
2. Orin 开机后等 1–2 分钟。

### 第 2 步：登录 Orin，检查基础状态（在 Mac 上）

```bash
ssh w@192.168.1.111
docker ps --format "{{.Names}}  {{.Status}}"   # go2w_humble、go2w_viz_bridge 都应是 Up
ip -4 -br addr show enP7p1s0                   # 应有 192.168.123.222 和 192.168.1.51/32
```

⚠️ **不要在 PC2 上运行 `~/start-mid360.sh`**。雷达同一时间只能给一台机器用。

### 第 3 步：启动导航

```bash
~/go2w/scripts/nav.sh start
```

- 导航在容器里后台运行，日志在 `~/go2w/data/logs/navigation.log`（上一次的日志会自动改名保留）。
- 设置初始位姿之前，planner 会一直打印"等待 map 坐标变换"，这是正常的，做完第 5 步就会继续。

### 第 4 步：在 Ubuntu 上打开 RViz

新开一个终端，**不要先 source 旧的 `mid360-env.sh`**：

```bash
bash ~/go2w_viz/go2w_rviz.sh
```

文件来源：Mac 上的 `~/Desktop/go2w/scripts/ubuntu/`。更新后用下面的命令重新拷到 Ubuntu：

```bash
scp -r ~/Desktop/go2w/scripts/ubuntu/* dx@192.168.1.167:~/go2w_viz/
```

### 第 5 步：设置初始位姿

在 RViz 里点 **2D Pose Estimate**，在机器人的实际位置按下鼠标，朝车头方向拖动后松开。确认红色的 scan 和地图上的墙对得上。位置大致准确即可，机器人走起来后 AMCL 会自己收敛。

### 第 6 步：解锁速度桥

```bash
~/go2w/scripts/nav.sh arm
```

脚本会先检查导航是否在运行、里程计是否健康、初始位姿是否已设置，然后才解锁。

### 第 7 步：发导航目标

在 RViz 里点 **2D Goal Pose**，在目标位置按下鼠标，朝期望的朝向拖动后松开。手里要拿着遥控器，随时准备接管。

### 第 8 步：结束

```bash
~/go2w/scripts/nav.sh stop
```

会先上锁，再停止导航和录包。

**如果开了录包，一定记得停**（在录包的终端按 Ctrl+C）。10-21 有一个录包忘了停，一直录了 28 小时，占了 1.2 GB。

### 中途休息

```bash
~/go2w/scripts/nav.sh disarm
```

导航不用停，回来后执行 `~/go2w/scripts/nav.sh arm` 就能继续，不用重新设初始位姿。

### 录包（可选，分析问题用）

```bash
cd /go2w/data/bags
ros2 bag record -s mcap -o 名字 /odom /odom_healthy /scan /cmd_vel /cmd_vel_nav /plan /amcl_pose /goal_pose /tf /tf_static /go2w_cmd_bridge/armed
# 结束时 Ctrl+C
```

分析工具：`python3 /go2w/scripts/calib/nav_smooth_check.py /go2w/data/bags/名字`（路径平顺性、跟踪偏差、速度）

### 用 Foxglove 代替 RViz（可选，任何电脑都能用）

容器 `go2w_foxglove` 开机自启，在 `ws://192.168.1.111:8765` 提供 WebSocket，不走 DDS，Mac 上直接用。

1. 装 Foxglove 桌面版（或浏览器打开 app.foxglove.dev），**Open connection → Foxglove WebSocket**，填 `ws://192.168.1.111:8765`。
2. 第一次：**Layout → Import from file**，选 `scripts/foxglove/go2w_layout.json`。
3. 设初始位姿：3D 面板右上角的发布按钮切到 **Pose estimate**，在地图上按下 → 拖朝向 → 松开（同 RViz 第 5 步）。
4. 解锁：点右侧 **🔓 解锁** 按钮（等同 `nav.sh arm`，但**不检查**初始位姿是否已设，先做第 3 步）。
5. 发目标：发布按钮切到 **Pose**，在地图上按下 → 拖朝向 → 松开（同 RViz 第 7 步）。
6. 右侧还有：解锁/里程计状态灯、上锁、清空局部 costmap、速度曲线、日志。

能转发、能发布、能调用的话题和服务都在白名单里：`ws/src/go2w_bringup/config/foxglove_bridge.yaml`，原始点云不转发。
改了白名单后重启：`docker restart go2w_foxglove`。

## 4. 其他用法（都在容器里执行）

| 目的 | 命令 |
|---|---|
| 只建图 | `ros2 launch go2w_bringup mapping.launch.py`，建完后执行 `bash /go2w/scripts/save_map.sh 地图名` |
| 只定位，不导航 | `ros2 launch go2w_bringup localization.launch.py map:=/go2w/data/maps/lab_20261021.yaml` |
| 换一张地图导航 | 把 `map:=` 改成对应地图的 `.yaml` |
| 只启动雷达（看点云） | `ros2 launch go2w_bringup lidar.launch.py` |

地图保存在 Orin 的 `~/go2w/data/maps/`（容器内为 `/go2w/data/maps/`）。

## 5. 运行中调参数（不用重启）

| 想调什么 | 命令（容器里执行） |
|---|---|
| 速度桥限速 | `ros2 param set /go2w_cmd_bridge max_vx 0.45`（还有 `max_vy`、`max_wz`、`cmd_timeout`） |
| Nav2 控制器速度上限 | `ros2 param set /controller_server FollowPath.vx_max 0.45`（还有 `vy_max`、`wz_max`） |
| 速度平滑器上限 | `ros2 param set /velocity_smoother max_velocity "[0.45, 0.1, 0.8]"` |

- 提速要**三处一起调**，只改一处不会变快；
- 运行中改的值，重启后就失效了。要长期生效，得改 `ws/src/go2w_bringup/config/` 下的 `nav2.yaml` 和 `cmd_bridge.yaml`。

## 6. 安全机制

速度桥（`go2w_cmd_bridge`）由内到外有以下保护：

1. **启动后默认上锁**，必须手动解锁才会发运动指令；
2. **限速**：前进 0.45 m/s，倒车 0.2 m/s，横向 0.1 m/s，转向约 46°/s（10-22 调整）；
3. **0.3 秒**没有新指令就自动停车；
4. **里程计不健康**（例如网线断开、雷达没有数据超过 0.5 秒）→ 立即停车并上锁，必须重启导航程序才能恢复；
5. 程序退出时先发停车指令；
6. Go2W 自身：1 秒收不到运动指令就会自动停下。

**遥控器始终可以接管。**

## 7. 常见问题

| 现象 | 原因和处理 |
|---|---|
| 解锁时提示"拒绝解锁：里程计不健康" | odom 中断过（多半是网线）。`Ctrl+C` 停掉导航，让机器人静止，重新执行第 3 步 |
| 日志里出现"FAST-LIO 输出中断……odom 已不可信" | 同上。另外检查网线：`journalctl -k \| grep "enP7p1s0: Link"` |
| RViz 里没有 scan | 先确认 PC2 没在跑雷达驱动；再检查 `ip route get 192.168.1.194`，应该走 `enP7p1s0`、源地址 `192.168.1.51` |
| RViz 里什么都看不到 | 检查 Ubuntu 的 IP 是否还是 `192.168.1.167`；检查 `docker ps` 里 `go2w_viz_bridge` 是否为 Up。IP 变了的话，要同时改 Orin 的 `docker/cyclonedds.xml` 和 Ubuntu 的 `cyclonedds_viz.xml` |
| 日志一直刷"Please set the initial pose" | 正常现象，做第 5 步 |
| scan 和墙对不上 | 重新做第 5 步，然后慢慢走几米，让 AMCL 收敛 |
| 点了目标不走，日志里有 `failed to create plan` / `no valid path found` | 目标点离障碍物太近，或者到目标的路被堵住了。在 RViz 里勾选 **Global Costmap**，目标要点在彩色区域以外，并且和机器人之间要有连通的空地。注意：避障看的是离地 0.10–0.8 m 的东西，椅子腿、箱子这类建图时看不到的低矮物体，也会挡路 |
| 不要单独启动 `control.launch.py` | `navigation.launch.py` 里已经包含了速度桥，再单独起一个会变成两个速度桥同时发指令。只重启速度桥时，要先停掉原来那个 |
| 机器人周围一圈都是障碍物，没法规划 | 先确认身边没人、没贴着家具；仍然有的话，清空局部代价地图：`ros2 service call /local_costmap/clear_entirely_local_costmap nav2_msgs/srv/ClearEntireCostmap "{}"` |
| Wi-Fi 连不上 Orin | 经 PC2 走有线：`ssh -o HostKeyAlias=192.168.1.111 -J unitree@192.168.1.142 w@192.168.123.222`；或用 USB-C 线：`ssh w@192.168.55.1` |
