> 一句话：**导航现在全部跑在 Go2W 自带的扩展坞（PC2）上，Orin（reComputer）不再运行导航，只作备用。**
> 本文只写 10-27～10-28 的变化；项目背景见 `Go2W导航项目交接说明.md`。那份文档和 `启动手册.md` 里"跑在 Orin 上"的说法已过时，以本文为准。

## 2. 日常操作（在扩展坞上）

```bash
# Mac：同步代码到扩展坞（默认目标仍是 Orin，务必带 dock）
scripts/sync.sh dock          # scripts/sync.sh all 两台都同步

# 扩展坞：编译 / 导航
docker exec go2w_humble bash /go2w/scripts/build.sh
~/go2w/scripts/nav.sh start | status | arm | disarm | stop | log
```

扩展坞没有免密 sudo，需要 sudo 的操作请让用户自己执行。

## 3. 10-27～10-28 的代码改动

| 文件 | 改动 |
|---|---|
| `docker/ros_env.sh`、`docker/cyclonedds.xml` | **按网卡自动识别机器**：有 `enP7p1s0` 是 Orin，否则是扩展坞；导出 `GO2W_WIRED_IF` / `GO2W_WIFI_IF` / `GO2W_LIDAR_HOST_IP`（Orin `.51`，扩展坞 `.50`），DDS 配置用这些变量 |
| `launch/lidar.launch.py` | 启动时以 `MID360_config.json` 为模板替换 host IP，写到 `/tmp/go2w_MID360_config.json` |

| `scripts/build.sh` | 编译前把 livox 的 `package_ROS2.xml` 复制成 `package.xml`（上游干净源码没有它） |
| `scripts/nav.sh` | 上锁 / 解锁的服务调用加 5 s 超时（速度桥没运行时 `stop` 会卡死） |
| **`scripts/planar_odom.py`** | **机身俯仰 / 横滚改用 Go2W 主控 IMU**（域 0 `/lowstate`，约 516 Hz，best-effort，以启动后 1 秒的站姿为基准）。参数 `tilt_source: robot|fastlio`，默认 `robot` |
| `ws/src/unitree_go/` | 新增，宇树官方消息定义（unitree_ros2 `668d1ec`），供上一条使用 |
| `config/nav2.yaml`、`config/cmd_bridge.yaml` | 调参：加速度 `[1.0, 0.5, 2.0]`、减速度 `[-1.2, -0.8, -2.5]`、`wz` 上限 1.2 rad/s、TwirlingCritic 权重 3、MPPI `batch_size` 600（原 1000 时扩展坞上控制循环约 7% 超时，改后为 0） |
| `scripts/calib/tilt_compare.py` | 新增：对比主控 IMU / 点云校平实际用值 / 地面拟合三种倾斜 |

### 为什么改 planar_odom（重要）

现象：提速后规划频繁失败（`no valid path`、`Starting point in lethal space`），机器人反复原地转圈、后退，走起来"卡"。
原因：**FAST-LIO 的俯仰 / 横滚在快速转向后会漂 5–10°**，而机身实际是平的（主控 IMU 与雷达地面拟合一致，偏差 < 0.5°）。
planar_odom 原来用 FAST-LIO 的姿态校平点云，结果把地面"抬"高，1.5–4 m 处 81–100% 的地面点超过 0.10 m 障碍阈值，被当成障碍。
改用主控 IMU 后：地面点超阈值比例降到 0%，用户实测规划失败和卡顿消失。FAST-LIO 的 x、y、yaw 仍然照用，没有问题。

## 4. 扩展坞系统层面的改动（已生效，重启保留）

- 有线连接 `Wired connection 1` 设为 `ipv4.never-default yes`：原来有线口网关 `192.168.123.1`（没有外网）抢了默认路由，导致上不了外网、不能对时。
- `/etc/systemd/timesyncd.conf.d/orin.conf` 改为 `NTP=ntp.aliyun.com ntp.tencent.com 192.168.123.222`：原来只向 Orin 对时，Orin 网线不插时时间会停在关机时刻。原文件备份在 `~/orin.conf.bak`。
- `unitree` 用户加入了 `docker` 组；装了 `docker-compose-v2`。

## 5. 注意事项 / 未完成

1. **雷达同一时间只能接一台机器**。在 Orin 上跑之前，先在扩展坞上 `nav.sh stop`，再执行 `scripts/sync.sh orin`，并在 Orin 上编译（会新编 `unitree_go`）。之后 Orin 的驱动会把雷达改回 `.51`。
2. **扩展坞的 USB 无线网卡经常掉线**（10-28 断了 4 次）：导航不受影响，但 SSH 和 RViz 会断。最后一次断线时**速度桥处于解锁状态**，重新连上后先执行 `nav.sh status` / `nav.sh disarm`。
3. 待查：**Go2W 导航时大多在抬腿走，很少用轮子滑行**。怀疑是 MPPI 全向模型一直在发小的横移指令（轮子不能横向滚动）。计划先做两个实验：遥控器只推前进看会不会滑；记录 `/cmd_vel` 的横移占比和主控的 `gait_type`。如果确认是横移导致，就改为 `motion_model: DiffDrive`、`vy_max: 0`。
4. 今天的站姿和 10-21 标定雷达时差约 3°（地面在 base 系下略低于 0），不会产生假障碍。需要时用 `scripts/calib/mid360_static_check.py` 重新标定。
5. 小问题：planar_odom 启动时有一条 `Publisher already registered` 警告（双域两个节点同名），无害；`tilt_compare.py` 退出时有 `terminate called` 报错，不影响结果。
6. `/sportmodestate` 在这台 Go2W 上**没有发布者**，主控状态请用 `/lowstate` 或 `/lf/sportmodestate`（都是 best-effort）。
